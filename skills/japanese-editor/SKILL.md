# 用途を切り替える日本語校正

このパッケージの [yomiyasu 2.0.0](../../vendor/yomiyasu/SKILL.md) を判断規則として使う。別に導入した同種スキルと規則を重ねて競合させない。引用した規則とスクリプトには [MIT](../../vendor/yomiyasu/LICENSE) と [Unicode notice](../../vendor/yomiyasu/UNICODE-LICENSE.txt) が適用される。

`japanese_editor_profiles` で用途と接続状態を取得する。ユーザーが述べた用途を選び、不明なときは文章から仮の用途を示す。小説と台詞では比喩、省略、反復、方言、一人称、語尾、曖昧さを残す。強さを上げても主張・比重・確度・文の働きと原文にない情報を足さない原則を変えない。

ホストの自分自身で修正候補を作り、`japanese_editor_review_proposals` へ原文と次の形式で渡す。独立版用の `generate=true` はホストからは使わず、追加の生成モデル呼び出しを避ける。

```json
{"text":"保存して下さい。","profile":"article","strength":"natural","edits":[{"before":"保存して下さい","after":"保存してください","reason":"補助動詞をひらがなにする","rule":"yomiyasu:用途と表記の扱い"}]}
```

`before` は原文に一度だけ現れる完全一致文字列とし、重複する場合は前後を含める。範囲を重ねず、互いに依存する修正は一件にまとめる。URLとコードを変えない。無修正は空配列。意図が決まらないところは原文を残し、本文外で短く尋ねる。

原文・修正案・理由を比較できる形で示す。ユーザーが依頼した編集範囲では編集を進め、単なる確認工程のために再承認を求めない。ファイルを保存する場合は原本を残し別名にする。元ファイルの更新を明示された場合はその指示に従う。

採用した修正だけを `japanese_editor_finalize` へ原文とともに渡す。エンジンが最終稿を組み立て、同じ本文を点検・照合する。返った `text` を最終稿とし、点検後に自分で書き換えない。最終稿を別途ユーザーから渡された場合の点検には `japanese_editor_check_final` がある。返る見直し候補は意味保持の証明でも品質点数でもない。未実行を成功と呼ばない。

`review_proposals` は、設定済みのローカルFlashを使って各候補を判定する。MCPは共有サービスを必要に応じて起動し、ホストごとにモデルを読み込まない。モデルの取得は別途明示的に行う。`decision.status=executed` のときだけ判定済みとして、`choice` の意味保持・意味変化・判断保留を伝える。未設定・実行失敗・時間上限では候補と原文が残る。理由は提案したモデルの説明であり、Deciderの説明ではない。CPU BF16の明示的な精度変更は応答の`precision_override`で確認できる。

判定は一件ずつ原文へ適用した候補が対象。`scope=excerpt` は前後の抜粋であり、全文や複数案を合わせた最終稿の意味保持を保証しない。ユーザーが意味を変える編集を依頼した場合は、その目的と照らして扱う。判定ラベルを自動採用・自動拒否の命令として扱わない。

`japanese_editor_prepare_decider` は、外部実装向けに要求JSONを準備するだけで送信しない。通常の校正では`review_proposals`を使う。

MCPが未登録なら [README](../../README.md) の導入方法を案内する。導入を依頼された場合はその範囲で登録する。グローバルな自動編集フックはこのスキルの対象外とする。
